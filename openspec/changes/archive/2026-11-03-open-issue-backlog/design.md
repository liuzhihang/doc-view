# Design

## Context

动机见 proposal.md。当前普通 Markdown 递归直接显示 Body 的 collection element 和 map key/value 合成节点；独立实体只提供 JSON 复制。依赖注释直接读取编译 PSI，未导航至源码。方法标签已有零散参数级支持，但没有接口级变量或实体字段级填充。#91 两张原图指向 Dubbo 多参数，当前实现已增加 @param 逻辑，必须复验而非假定仍缺失。#90 模板生命周期已有测试和历史验收，保持并重跑。

## Goals / Non-Goals

- Goals：通过真实 PSI 和 Markdown 断言固定六项反馈的可见结果；所有新增行为先 RED 后 GREEN。
- Non-Goals：不升级平台、依赖或插件版本，不改变上传 payload，不实现路由组合的多文档输出，不自动下载 sources，不恢复字节码中已丢失的 Javadoc，不混入原工作区待提交功能。

## Decisions

1. 使用 IntelliJ 公共 `getNavigationElement` 为编译字段找同名有效源码字段。仅元数据用源码，原字段类型、泛型、写回身份不变。比猜 Maven/Gradle 缓存路径、解压源码更准确且无新增磁盘/网络副作用。
2. 接口 `since/version` 作为 DocView/DocViewData 字段；默认中英模板非空才展示，用户模板可显式使用。实体字段读取自身标签；标量参数维持方法标签。删除错误的“描述含标签文字则清空”过滤。不自动继承类级标签。
3. 路径解析优先显式 value 的第一项，其次 path 第一项，使用常量计算并沿用斜杠规范；空数组和未解析值安全降级。保持一个方法一篇文档。模板持久化仅在复现失败时修复。
4. 参数描述使用 PSI 的参数名精确匹配，处理空标签、多行及名称前缀冲突，Dubbo/Spring 共用已存在工具。原截图作为回归；如果当前已通过记录已有修复。保持 Swagger 描述优先级。
5. 通过表格投影隐藏合成节点而不删除底层 Body 树，重算显示前缀；普通与分表输出共享。使用标记区分真实 element/key/value 字段。JSON、编辑树、平台 payload 不变。范围是现有解析树的显示；不新增此前未展开的 List<List<T>> 等任意容器解析。
6. 独立编辑器增加 Markdown 复制 action。提交正在编辑的单元格，用当前树的 DTO 快照渲染，不写回源码；沿用后台任务、取消/关闭保护。复用表格投影，空/未加载/disposed 不复制。文案进入两份本地化资源。

## Risks / Trade-offs

- 多个服务共用 PSI 与缓存 → Spring/Dubbo 请求/响应、sources 关联后缓存失效、泛型和递归回归。
- 分表输出隐藏中间节点影响层级 → 测试 List/Map 嵌套、标量容器、真实同名字段、空/递归节点及 JSON 不变。
- 原工作区已有另一平台升级 → 隔离于已提交 Java21/IU2026.1 基线，不推送未验证升级内容。
- UI自动测试不等于原生交互 → 运行 runIde 对实体复制烟测；若环境阻碍，记录具体未验证项，不冒称通过。

## Migration Plan

新模板变量只扩充；无标签输出保持既有 golden。无需设置迁移。开发分支可回滚本轮提交；不合并、不发 tag、不发布 Marketplace。未交付修复保持 Issue 打开。归档同步新增长期规格，验证报告明确本地与远端状态。
