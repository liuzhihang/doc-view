# Proposal

## Why

Doc View 的设置分散在不同入口，规则来源与模板变量不容易理解；主设置页还把普通接口选项错误地绑定到行标记，并展示没有实际效果的选项。此次整理设置层级和模板反馈，让用户能找到配置、判断配置作用并在保存前检查模板结果，同时保持现有文档生成规则。

2026-10-20 用户在原生验收中反馈规则说明过重、分组方框过明显。本次追加调整生成规则页面：使用原生浅分隔线、分组级说明图标和可换行的短灰字；详细来源顺序与固定规则放入悬浮帮助，实际生成与保存语义保持。

## What Changes

- 将项目级 Doc View 设置整理到 Tools 下，按常规行为、生成规则、模板与输出、平台集成组织；平台集成下保留 YApi、ShowDoc、YuQue 各自页面。
- 将行标记与普通接口识别/扫描选项设为独立可用；把现有生成规则按标题、接口名称、描述、必填标记和字段名来源分类，并说明固定规则与来源顺序。
- 保留模板编辑器和现有 Markdown 生成语义，增加可搜索、可插入的变量说明、仅作用于草稿的恢复默认操作、固定虚构 Spring/Dubbo 示例预览及错误反馈；模板与输出页改为“模板编辑 / 预览结果 / 输出选项”三个工作区，按需显示变量侧栏，减少首屏常驻控件。
- 将模板参数分表、两类参数表嵌套层级前缀、合并导出等现有输出选项放入模板与输出页；移除无实际行为的 `hideLeft` 和 `excludeParamTypes` 设置及其缓存哈希引用，保留实际用于参数类型过滤的 `excludeParameterType`。
- 为设置页、选项和模板帮助增加中英文搜索关键词；设置页在默认浏览器打开对应 GitHub 使用指南；保持当前项目作用域及集成凭据、上传行为边界。

## Capabilities

### New Capabilities

- `configuration-experience`: 描述 Doc View 设置层级、配置分组与独立开关、模板帮助和预览行为。

### Modified Capabilities

无。

## Impact

涉及设置 Configurable 与 Swing 表单、模板设置与预览、`plugin.xml` 设置入口、设置本地化文本、模板渲染验证和设置行为测试。生产实现继续使用 Java 与现有 IntelliJ Platform API，不新增依赖；本 change 不改变默认 Markdown、上传 payload、平台凭据存储或 PSI 解析规则。
