# Design

## Context

参见 [proposal.md](proposal.md) 的问题描述。当前导出器把身份哈希、模块、框架、接口和两条链接放在同一张 Markdown 表格中。长身份列使 IDEA 分屏预览中的可读列被压缩。稳定身份、文件名和索引所有权 marker 已由项目文档导出实现维护。

## Goals / Non-Goals

**Goals:**

- 让索引以纵向结构展示模块、类和方法，并让可读签名及文档/源码入口靠近首屏。
- 在隐藏的 Markdown 元数据中保存完整可逆 identity 和对应 SHA-256，供后续工具读取。
- 保持现有接口页面文件名、来源链接、框架信息、整体索引 marker/hash、冲突检测和排序确定性。

**Non-Goals:**

- 不改变 identity 字段、编码算法、SHA-256 或 API 页面路径。
- 不重新定义项目扫描、Markdown 模板、导出入口、发布/冲突流程、IDE 搜索、MCP 或 wiki。
- 不增加配置、依赖或专用索引格式；不保证 IDEA 不同窗口宽度都能显示任意长签名的一整行。

## Decisions

### 按模块与类分组，方法使用短链接标签

`index.md` 正文按模块名和全限定类名排序生成二级/三级标题；每个方法单独占一条纵向列表项，展示参数类型完整的 `displaySignature()`、框架名，以及短标签的 Markdown 与源码链接。按稳定键排序模块、类和方法，重复导出输入相同则输出字节相同。短链接标签避免将长文件路径显示为横向文字。

选择纵向目录而非保留表格并缩短身份列，是因为哈希对阅读者没有定位价值，且 IDEA Markdown 分屏对宽表的首屏可读性已经出现问题。模块和类标题提供上下文，方法行只重复需要区分重载的签名。

### 每个方法条目携带隐藏身份元数据

在每个可见方法条目前放置一行版本化 HTML 注释，内容包含 `ProjectDocumentIdentity.canonicalForm()` 与 `sha256()`。canonical form 已编码模块、项目相对源码路径、全限定类名、方法名、参数类型列表，使用现有可逆身份表示；摘要仍对应当前页面文件名。该注释与索引整体所有权 marker 一样属于索引正文，因此自然纳入现有 index body hash。

选择隐藏注释而非独立的身份列，因为身份由工具使用、不是阅读者的导航信息。选择内联注释而非旁路 manifest，可让索引和身份信息一起复制、提交与移动，不改变输出文件集合。

### 只改 index 正文 renderer

页面正文、稳定页面文件名和链接计算保持原样。索引已有的 module、framework、interface、source、document 信息全部保留，只从表格改成分组标题和方法条目。测试覆盖不同模块/类、同名重载、身份元数据、源码/文档相对链接、确定性字节和原文件名不变；用户指南只更新索引阅读说明。

## Risks / Trade-offs

- [源 Markdown 仍包含一行较长的 Base64 canonical identity] → 该行是隐藏注释，不参与预览宽度；可读方法行只显示签名和短链接标签。
- [很长的真实方法签名仍可能在窄窗口换行] → 不再把固定长度 hash 与其它字段并排；本 change 不截断参数类型或损失重载信息。
- [Markdown 引擎对 HTML comment 的显示不同] → 注释放在独立行；用生成文本测试保证原始 Markdown 有完整元数据，最终分屏外观仍需主 Agent 后续原生复验。
- [旧索引 marker 仍有效但正文布局过时] → 导出器使用现有 body hash 发现目标与新内容不同并正常替换受管理索引；不改变索引 marker 版本或身份算法。

## Migration Plan

无文件迁移或设置变更。下一次项目文档导出会以新布局替换通过现有所有权校验的 `index.md`；已手动修改或无有效 marker 的索引仍按现有冲突保护处理。接口页面、旧页面保留和用户文件处理方式不变。
