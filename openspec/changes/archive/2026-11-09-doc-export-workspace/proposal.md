# Proposal

## Why

当前批量与窗口导出在用户确认“覆盖”后仍以追加方式写入，重复操作会把同一接口文档不断累加；项目 PSI 快照也没有统一的 read-action 与文件 IO 边界。项目内可检索、可复用的 API 文档需要稳定来源身份、可重复生成和保护用户修改的冲突规则。

## What Changes

- 增加明确的“导出项目文档”动作，将当前项目发现到的 Spring、Feign、Dubbo 接口导出到项目内的 Markdown 文档目录；每个接口使用稳定身份和相对源码引用，并生成便于人和 AI 顺序读取的项目索引。
- 同一源码快照重复导出时，确定性地更新由 Doc View 管理且未经用户修改的目标文件，不追加内容；遇到未由 Doc View 管理或已被用户修改的同名文件时，预检后拒绝整批覆盖并报告冲突。
- 将 PSI 读取/文档快照与磁盘写入分成后台阶段，支持取消、有限失败报告和逐文件安全发布；保留无关文件，不因重导出清理项目内容。
- 将现有窗口合并导出和目录选中节点批量导出改为后台 read-action 文档快照，再在 read action 外写盘；单文档已生成内容的复制/保存流程保持原用途。
- 修正现有窗口及目录批量导出在确认覆盖后仍追加的行为，使确认具有实际替换语义；保留单文档导出、复制和临时预览文档的用途。
- 让生成的普通 `.md` 文件可被 IDEA 常规文本搜索发现；不新增 IntelliJ 自定义索引或 MCP 工具。

本 change 不导入旧导出文件，不为旧文件名、模板或数据格式做迁移/兼容；旧未标记文件与用户文件一样按冲突处理。

## Capabilities

### New Capabilities

- `project-document-export`：定义项目范围 Markdown 导出的身份、来源链接、索引、重复导出、冲突保护和任务边界。

### Modified Capabilities

无。

## Impact

- 影响 Doc View Tool Window 的导出动作、现有目录/窗口批量写入路径，以及负责 PSI 快照、Markdown 渲染和文件发布的 Java 服务。
- 在项目中新增 `docs/doc-view/` 下的普通 Markdown 页面与 `index.md`；目录内已有的无关内容保持原样。
- 新增 PSI fixture、稳定路径/重载/多模块 identity、模板渲染、冲突/取消/失败和重复导出测试，并更新用户指南与输出 golden。
- 不增加生产依赖、语言、IDE extension、自定义索引或 MCP 能力。
