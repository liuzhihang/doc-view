# Design

## Context

发布范围见 [proposal.md](proposal.md)。活动 change 是功能契约和未完成事项的事实来源。`docs/release-checklist.md` 中 2026-11-09 的一次性例外允许把明确列出的原生验收缺口留给本次发布后的维护者人工验证；已知功能问题和最终自动门禁仍须完成。早期候选结果不能证明最终 1.6.0 包通过。

2026-11-09 远端审计时，GitHub 与 Marketplace 最新版本为 1.5.0，没有占用 1.6.0；远端 `develop` / `master` 为 `877f0c9`。这只是审计快照，发布前须重新核对。最终插件 descriptor 和 ZIP 必须含 `require-restart="true"`，仍须从最终制品实际读回。

## Goals / Non-Goals

**Goals:**

- 让 1.6.0 源码 revision、插件 descriptor、ZIP/JAR 哈希、测试与 Verifier 报告、原生证据、tag、GitHub Release 和 Marketplace 更新拥有可追踪的一致身份。
- 在面向用户的发布文案中，清楚区分已交付范围、明确排除的 MCP/Skill 工作以及未完成的原生场景。
- 若某功能验收仍不完整但依一次性例外发布，仍保留该功能 change 中未完成的任务。

**Non-Goals:**

- 在发布协调 change 中重写 HTTP 生成、Schema 编辑、项目文档库或 IDEA 平台行为契约。
- 交付正式 Doc View MCP 工具、Skill 安装/更新器、语义搜索，或承诺热更新/热卸载。
- 批量完成或归档功能 change，或把较早候选结果当作最终 1.6.0 包验收。

## Decisions

1. **以 1.6.0 为发布目标，但发布前重新核对远端。** 最新审计时版本尚未占用且 1.5.0 为当前最新版本。创建发布提交、tag 前重查 GitHub、Marketplace 与远端分支；若版本已占用或分支条件变化则先停止并重新评估。

2. **以功能 change 作为发布内容事实来源。** 发布摘要只描述最终 revision 实际包含的功能。Java 25 / IDEA 263、HTTP 请求生成和 UI、Schema 行为、JSON 文档库分别由活动 change 跟踪；正式 MCP/Skill 明确排除。不得暗示已有实时源码 MCP 查询或 Skill 安装能力。

3. **冻结并验证唯一制品身份。** 固定实现 revision 后记录 commit、最终 ZIP/JAR 路径与 SHA-256、descriptor 字段、测试总数、Verifier 目标/结论及原生测试所用 IDEA build/profile。生产输入变更后，相关制品证据必须重建或重验；历史候选单独列示。

4. **把发布例外限制在未完成原生验收。** 仍须完成全量测试、项目配置检查、构建与 Plugin Verifier。发现已知功能问题先修复再复验。对未运行的原生场景注明场景、原因/边界及后续人工验证方式，不标通过，也不勾选对应功能任务。此例外仅适用于本次发布。

5. **将重启要求纳入制品契约。** 最终 ZIP 的 `plugin.xml` 必须读回 `require-restart="true"`。发布说明指出安装、更新和卸载需 IDE 重启后生效；不宣称该设置修复了现存类加载器引用或实现了原位卸载。

6. **通过常规发布渠道执行并回读。** 最终制品门禁通过后，按获准的 `develop` 到 `master` 流程合入、创建指向发布提交的版本 tag、发布 GitHub Release 和 Marketplace 更新，再分别回读状态与制品哈希。上传成功不等于 Marketplace 已审核或公开上架。

## Risks / Trade-offs

- [审计后远端分支或公开版本发生变化] → 发布提交/tag/upload 前重新核对；条件不符时停止，避免覆盖或复用版本。
- [晚到源码或元数据变更使证据对应另一个包] → 所有报告和原生运行都关联最终 ZIP/JAR 哈希；相关输入变更后重建并重验。
- [一次性例外被误读为完整验收] → 发布记录按场景标示通过、部分、未验证，并保留活动 tasks 未勾选。
- [重启要求被误读为卸载修复] → 明确它只描述生命周期生效方式，不会移除已观察到的类加载器引用。
- [JSON 文档库被误读为实时源码或 MCP 能力] → 说明它是生成后落盘的项目文档快照，并写明 MCP/Skill 未交付。

## Migration Plan

1. 完成获准的 1.6.0 源码和 descriptor 状态，并重新审计版本与远端分支。
2. 对冻结 revision 执行全量必要测试、项目配置检查、构建及 Plugin Verifier；审计最终包并读回版本、兼容基线、重启标志和制品清单。
3. 在同一最终包上执行可完成的原生场景；把其余缺口列入一次性例外说明，相关功能任务继续保持未完成。
4. 范围和制品固定后更新正式发布元数据，再按授权流程创建发布提交/tag 并发布；回读所有远端状态及哈希。
5. 若需回滚，停止继续上传，保留已发布制品和证据，并按仓库发布清单处理；不覆盖既有版本，修复发布使用新的 patch 版本。

## Open Questions

无阻塞本计划的问题。最终测试统计、制品哈希、原生通过/未验证项、发布提交、tag 与 Marketplace 审核状态必须在执行时取证，不在计划阶段预填。
