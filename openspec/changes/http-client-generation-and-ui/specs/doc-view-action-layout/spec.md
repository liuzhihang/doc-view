# Spec Delta

## Purpose

定义 Doc View 工具窗口和目录菜单的动作组织方式，使用户能区分打开文档、导航源码和生成 HTTP 请求，并能在正确的项目上下文中找到维护操作；保持已有功能可达、平台图标风格及中英文界面一致，不引入新的设置或导航层级。

## ADDED Requirements

### Requirement: 常用工具栏与维护操作分开

主工具栏 SHALL 按刷新、导出下拉、上传、展开全部、折叠全部组织，最多使用两个分隔线，且无首尾或相邻分隔线。设置和清缓存 SHALL 仅作为 Doc View 维护项放入工具窗口原生 `…` 菜单，不再作为主工具栏按钮或目录节点右键中的清缓存项。平台原有窗口菜单项 SHALL 保留。

#### Scenario: 正常工具窗口布局
- **WHEN** 用户打开 Doc View 工具窗口
- **THEN** 主工具栏包含上述五个常用入口，导出仍是包含现有两种导出的单个下拉
- **AND** 主工具栏没有设置或清缓存按钮，`…` 菜单内二者均可找到

#### Scenario: 目录右键与窗口菜单
- **WHEN** 用户分别打开方法节点右键和工具窗口 `…` 菜单
- **THEN** 项目级清缓存只在后者出现，不暗示只清当前方法
- **AND** IDE 原生移动、显示模式等窗口菜单行为不受影响

### Requirement: 维护动作绑定所属项目并保持原语义

设置 SHALL 打开所属项目的 Doc View 设置；清缓存 SHALL 清理所属项目的 Doc View schema 缓存，不删除手写 Scratch、HTTP 草稿或导出 Markdown。动作移动 SHALL 保持其身份和快捷键可达性，不能依赖当前外层编辑器属于同一项目，不能改变既有缓存安全边界。

#### Scenario: 两个项目独立维护
- **WHEN** 打开 A/B 两个项目，从 A 的 Doc View 窗口菜单执行设置或清缓存
- **THEN** 只作用于 A，B 的设置、缓存及所有文档文件保持不变

#### Scenario: 清缓存后草稿保留
- **WHEN** 项目同时存在手写 Scratch、用户编辑的 HTTP 草稿与导出文档，用户执行清缓存
- **THEN** 这些文件及未保存编辑保持不变，菜单正常关闭

### Requirement: 文档源码和 HTTP 动作名称明确

原目录 `Open` SHALL 命名为“打开 Markdown 文档”/“Open Markdown Document”，源码导航继续使用平台动作。采用原生生成路线时 HTTP 入口 SHALL 为“在 HTTP Client 中打开”/“Open in HTTP Client”；采用自生成路线时 SHALL 为“生成 HTTP 请求”/“Generate HTTP Request”。提示 SHALL 说明生成可编辑草稿，执行请求需由用户另行操作。

#### Scenario: 查看方法菜单
- **WHEN** 用户查看方法节点右键菜单
- **THEN** 可以从名称区分文档、源码和 HTTP 草稿操作，不出现泛化的 `Open` 或仅 `HTTP Client` 名称

#### Scenario: 名称与最终实现一致
- **WHEN** 生产实现路线已在本 change 决策记录中确定
- **THEN** 所有 Doc View HTTP 入口使用对应路线的一组名称，不同时呈现两种生成模式

### Requirement: 目录动作按目标和平台状态启用

文档和 HTTP 动作 SHALL 仅对相应有效方法提供执行入口；非方法节点的这两个操作在目录菜单中隐藏，快捷键或程序化触发时无副作用。HTTP 还 SHALL 排除 Dubbo/普通非 HTTP 接口。索引中或依赖不可用时，适用方法的动作 SHALL 禁用并提供原因；复杂不支持输入可在后台校验后反馈，不在菜单更新中做重解析。

#### Scenario: 选择类模块或空白
- **WHEN** 用户选择类、模块或空节点
- **THEN** 目录菜单不显示打开 Markdown 和 HTTP 请求动作
- **AND** 触发它们的既有 action 身份不会展开目录或生成文件，展开操作仍由独立动作承担

#### Scenario: Dubbo 方法
- **WHEN** 用户选择有效 Dubbo 方法
- **THEN** 打开 Markdown 和源码导航仍按既有规则可用，HTTP 入口隐藏

#### Scenario: 索引中和源文件失效
- **WHEN** 已选 HTTP 方法在索引未就绪时显示菜单，或节点源码随后失效
- **THEN** 索引中禁用生成并说明原因；失效后不解析、不发布草稿、不抛出未处理异常

### Requirement: 同一动作具有一致语言与平台图标

新增或调整的名称、tooltip、取消/失败/不支持提示 SHALL 跟随 IDEA 英语或简体中文界面，其他语言回退英语。同一动作在工具栏、目录菜单、`…` 和 Find Action 等已有入口 SHALL 保持一致名称及语义对应的平台图标；品牌 SVG 与节点图标不重绘，不为每个上传平台补充图标。

#### Scenario: 两种语言和主题
- **WHEN** 在英语/简体中文、浅色/深色主题及 Compact Mode 中查看调整后的入口
- **THEN** 名称、图标和提示可辨认，没有缺失资源键或裁切导致无法识别操作
- **AND** HTTP 内容、业务名称和生成文档不会因 UI 语言改变

#### Scenario: 键盘与窄窗口
- **WHEN** 使用键盘打开目录菜单和窗口菜单，或在窄工具窗口中寻找维护操作
- **THEN** 设置、清缓存、文档和适用的 HTTP 操作均可按各自入口规则到达，焦点和 tooltip 能表达当前动作

### Requirement: 布局精简不改变现有业务操作

现有刷新、导出范围、上传平台选择、复制、预览、参数编辑、目录排序/搜索、双击/Enter 文档打开与用户保存的窗口布局 SHALL 保持既有行为。移动动作和打开菜单 SHALL NOT 触发上传、自动生成请求、自动展开目录或重置 IDE 布局。

#### Scenario: 菜单仅被打开和关闭
- **WHEN** 用户打开导出、上传或窗口维护菜单，随后按 Esc
- **THEN** 没有生成、上传、清缓存、设置修改或目录展开副作用

#### Scenario: 原有文档快捷行为
- **WHEN** 用户双击或按 Enter 打开有效方法，或用原有导出/复制入口处理文档
- **THEN** 仍按既有文档 contract 工作，不被 HTTP 路线或菜单重组替代

### Requirement: 目录方法搜索包含完整方法说明

目录 Speed Search SHALL 按方法完整签名、现有业务标题和当前说明规则解析出的完整方法说明匹配。方法说明在节点创建时读取，并供 tooltip 与搜索文本复用，不得在每次按键时重新解析 PSI。搜索 SHALL NOT 改变方法节点的显示标题、导出标题或 Markdown/HTTP 文件命名；现有 15 字符业务标题规则保持不变。

#### Scenario: 搜索显示标题以外的说明关键词
- **GIVEN** 一个方法的说明为 `Nativepageitem23 ... tailneedle`，其中显示业务标题仍按现有规则截为 15 个字符
- **WHEN** 用户在目录 Speed Search 中输入完整说明尾部的 `tailneedle`
- **THEN** 该方法节点应被匹配，平台 formatter 提供给 Speed Search 的文本包含完整方法说明
- **AND** 方法行标题和 Markdown/HTTP 文件路径仍保持原有 15 字符命名结果

### Requirement: 参数编辑动作明确表达输出与写回
参数编辑器底部 SHALL 提供三个纯图标按钮，依次为复制 JSON、复制 Markdown 和写回源码，使用外形可区分的平台图标，不显示常驻按钮文字。完整中英动作名及说明 SHALL 保留在 tooltip 和无障碍名称中，支持键盘焦点。提示 SHALL 分别说明复制字段示例 JSON、复制当前参数 Markdown、将描述和必填信息写回源码。复制、写回及 Undo 行为保持不变；复制不得隐式写回，写回必须主动点击对应动作。

#### Scenario: 图标区分输出和写回
- **WHEN** 在深浅主题与中英界面查看参数编辑器
- **THEN** 底部只显示三个可辨认的图标，JSON 和 Markdown 通过类型符号区分，写回使用确认符号
- **AND** hover 或键盘焦点可获得完整动作名，在窄窗中三项均可达，没有文字挤占或按钮裁切
- **AND** 复制仍使用原业务处理，未点击写回不会修改源码

#### Scenario: 参数图标动作的键盘可达性
- **WHEN** 屏幕阅读器选项关闭，用户在参数弹窗内使用 Tab 或 Shift+Tab
- **THEN** 三个底部动作均可获得键盘焦点，并提供对应本地化动作名称
- **AND** 按 Space 只执行当前聚焦动作，复制不写回，写回仍可通过原生 Undo 撤销；工具栏更新后保持可达

#### Scenario: 从字段表返回动作按钮
- **WHEN** 用户在参数表编辑字段后按 Ctrl+Tab 或 Ctrl+Shift+Tab
- **THEN** 有效编辑先提交到当前草稿，焦点按方向离开表格并留在本弹窗的控件循环中，不触发 IDEA 编辑器切换
- **AND** 表格内原有 Tab/Shift+Tab 单元格导航保留；无效编辑不能被强制丢弃，局部快捷键随弹窗释放

### Requirement: 设置说明具有次级文字层级
设置页的非编辑说明 SHALL 使用平台小号 UI 字体和主题感知的说明文字颜色，不采用编辑器等宽字体、硬编码灰色或与主选项同等级的字号。说明 SHALL 保持可换行、不抢键盘焦点，深浅主题可读；设置值和 Apply/Cancel 语义不变。

#### Scenario: 常规设置解释两个独立开关
- **WHEN** 查看 gutter 标记和普通接口识别开关的说明
- **THEN** 说明比开关文字小，并使用主题的次级前景色
- **AND** 宽窄窗口都能换行阅读，开关和说明关系清晰

### Requirement: 弹窗不跨应用强制置顶
Doc View 预览和参数弹窗 SHALL 使用正常应用窗口层级，切换到其他应用时不得遮挡该应用的前台窗口。Pin 仅保持 IDEA 内的弹窗，不授予跨应用置顶。切换应用 SHALL NOT 自动写入源码、复制、上传或丢弃尚未确认的参数编辑；返回 IDEA 后可继续编辑或显式取消。

#### Scenario: 切换应用后继续编辑
- **WHEN** 用户在参数弹窗修改描述但尚未写回，切换到另一个应用，再返回 IDEA
- **THEN** 其他应用的前台窗口没有被 Doc View 强制覆盖，参数草稿保持可继续编辑
- **AND** 源码未被自动写回；Pin 开与关分别验证

#### Scenario: 预览的子窗口和取消
- **WHEN** 用户从预览打开导出路径选择、设置或上传选择，再取消
- **THEN** 子窗口正常可操作，不因窗口层级调整意外执行操作
- **AND** Escape、外部点击和 Pin 的已有应用内行为仍按各自约定工作

### Requirement: 图标审查覆盖全部生产入口
本次 SHALL 审查生产 Java、descriptor、form 和自有 SVG 中的全部图标引用，按实际动作语义、同动作一致性、用途尺寸及主题适配记录保留或替换决定。合理的平台图标和品牌图标 SHALL 保留，文件类型图标用于参数复制时 SHALL 以不同类型符号和明确 tooltip 区分输出格式，写回使用独立操作图标；无图标的平台选择子菜单不要求补品牌图标。

#### Scenario: 图标审查记录可核对
- **WHEN** 完成本轮图标检查
- **THEN** 审查清单覆盖所有图标来源，列出需更改项及其理由
- **AND** 资源可解析检查与最终包原生外观验证分别记录，未查看的主题或入口不标为通过

### Requirement: 注册动作组具有可读的 Keymap 标题
所有带 ID 注册的 Doc View 动作组 SHALL 提供非空的英文 fallback 和对应中英文 `group.<id>.text`，使 Keymap 使用可读名称而非内部 ID。补齐标题 SHALL NOT 改变组 ID、动作顺序、popup/compact 属性、快捷键或启用尚未启用的入口。

#### Scenario: Keymap 展示 Doc View 动作组
- **WHEN** IDEA 构建 Keymap 动作树或用户搜索 Doc View
- **THEN** Doc View 组以可读的本地化标题显示，没有本插件引起的空标题警告
- **AND** 既有动作仍属于原组，未激活的浮动工具栏保持未激活
