# i18n

本文档定义 Doc View 的国际化和本地化维护策略。当前仓库已有中文 README、中文注释和 `messages/DocViewBundle.properties`，未来应逐步让用户可见文案有统一来源。

## 范围

i18n 覆盖：

- IDE action 文案。
- tool window、preview、settings、参数编辑表单文案。
- 通知和错误提示。
- Markdown 模板默认文案。
- 上传平台错误说明。
- README、docs 和 release notes。

不覆盖：

- Java 类名、方法名、包名。
- OpenSpec change name。
- 外部平台原始错误码。
- 用户自定义模板中的自由文本。

## 当前状态

- `src/main/resources/messages/DocViewBundle.properties` 存在。
- `DocViewBundle` 提供 message bundle 访问入口。
- `plugin.xml` 中仍有大量 action/displayName text。
- 部分 UI 和日志文本直接写在 Java 或 form 中。
- README 和若干代码注释使用中文。

## 维护规则

- 新增用户可见 UI 文案时，优先放入 message bundle。
- 修改 `plugin.xml` action text 或 configurable displayName 时，需要考虑是否同步到 bundle 或记录理由。
- 错误提示应可被用户理解，避免只显示异常类名。
- 日志可以偏技术化，但不能包含 token。
- 生成 Markdown 的默认语言应与模板策略一致，不强制覆盖用户自定义模板。

## Message Key 规范

建议 key 按区域命名：

- `action.preview.text`
- `action.upload.yapi.text`
- `settings.yapi.title`
- `notification.upload.failed`
- `template.default.section.request`

key 应稳定。删除或重命名 key 前需要检查所有引用。

## 生成文档语言

Doc View 生成的 Markdown 文档受模板影响：

- 默认模板应使用一致语言。
- 用户自定义模板拥有最高优先级。
- Contract 中应记录模板变量，不应把语言选择写死在 PSI 解析层。
- 如果未来支持多语言模板，应通过 `TemplateSettings` 或明确配置控制。

## 平台集成文案

YApi、ShowDoc、YuQue 上传相关提示应：

- 区分配置错误、认证失败、网络失败、服务端错误。
- 避免暴露 token、cookie 或完整敏感 URL。
- 尽量包含用户下一步操作建议。
- 保持平台名称原文。

## 文档语言策略

- 面向维护者的 docs 可以使用中文。
- 对外 README、Marketplace 描述和 changelog 可根据发布受众维护中英文内容。
- 若同一信息存在多语言版本，release 前需要检查内容一致。

## 未来工作

- 梳理所有硬编码 UI 文案。
- 将新增用户可见文案迁移到 bundle。
- 增加英文或中文变体 bundle 时，先提出独立 OpenSpec change。
- 为默认模板语言增加 contract 和验证。
